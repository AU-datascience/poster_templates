Theming & Brand

Note

Skip this page unless you’re re-theming. If you’re just writing poster content on the templates as shipped, you don’t need to know Bootstrap (Bootstrap contributors, n.d.) or SCSS (Sass, n.d.) at all — the colors and fonts are already set up. Come back here only if you’re forking for a different organization’s palette, or troubleshooting a contrast/color regression.

1 Re-coloring the templates

If you fork this repo for another organization, the palette lives in a small number of places. The check-contrast.R exists so you can prove your new colors are still accessible against WCAG (Initiative (WAI), n.d.) rather than assume it:

  1. scss/poster-common.scss: the $au-* tokens under scss:defaults drive the whole web version.
  2. _brand.yml: the same palette for Quarto’s brand-aware theming. Keep the two in sync; some Bootstrap variables come from here rather than from the stylesheet.
  3. Print footers are per template: footer-color and footer-text-color in each poster.qmd YAML.

Then re-run the audit:

Rscript scripts/check-contrast.R                 # fails below WCAG AA
Rscript scripts/check-contrast.R --require-aaa   # fails below AAA

It parses your new hex values out of the stylesheet and each template’s YAML and re-measures every pair, so the check follows your colors instead of the ones committed here. render-all.R runs it as part of the full suite.

Some technical considerations to ensure proper contrast, all covered by the script:

  • The banner is a gradient. Text has to clear the threshold against the lighter stop, not just the dark one.
    • Auditing only the dark stop can cause issues.
    • The script reads both stops out of the linear-gradient() declaration and checks each separately.
  • The gradient’s light stop is capped by its text, not by taste. White normal-size text needs 7:1 for AAA, which puts a hard ceiling on how light $au-blue-banner can be; hence a dedicated token rather than reusing $au-blue.
    • Note the label originally used a dimmed tint, and a tinted label is still normal-size text, so AAA would have demanded 7:1 of the tint and forced the light stop nearly to navy, flattening the gradient.
    • The labels are plain white instead and read as secondary through case, tracking, and weight, which keeps about half the gradient’s luminance range.
  • Opacity silently undoes contrast. Quarto’s own stylesheet sets opacity: .8 on .quarto-title-meta-heading.
    • Left in place, white at 80% over the light stop composites to roughly #d6dee7 and measures 5.31:1 which is AA, not the 7.21:1 the color alone suggests.
    • poster-common.scss overrides it back to opacity: 1; if you introduce translucency anywhere, remember the audit reads declared colors, not composited ones.
  • Accent colors and text colors are held to different bars. WCAG asks 3:1 of large text and graphics, but 4.5:1 (AA) or 7:1 (AAA) of normal-size text.
    • $au-blue is perfectly fine as a banner and border color yet was not fine as link text, which is why $au-blue-text exists as a separate darker token so links can darken without darkening the banner.
    • Size is the other lever, and the script reads each rule’s declared font-size rather than taking anyone’s word for it: a heading at 24px or more (1.5rem at the default root size) is audited as large text automatically, which is how 02’s red headings reach AAA without touching the red.
    • Shrink such a heading back below 24px and the audit silently re-classifies it as normal text and the stricter bar returns.
  • Inline code inherits the brand grey. Bootstrap derives --bs-code-color from it, so $au-grey sets both the acknowledgments/references block and every `inline code` span.
    • These templates use a lot of inline code, so that pair is audited explicitly.
  • Rule colors are parsed, not restated. The script reads the color: and background: declarations straight out of the four stylesheets (resolving palette variables and gradient stops), so editing a rule such as the ethics panel’s cream background is picked up automatically.
    • Its source column shows where each value came from. The exceptions are Bootstrap-derived variables (--bs-body-color, --bs-code-color, $link-color), which no rule states; those resolve from the palette instead.
  • Renaming a class breaks the audit loudly. A lookup that finds no matching selector or property is a hard error naming the failed selector, not a silently skipped row, so the audit cannot quietly stop covering something you renamed.
  • A rule that matches nothing gets no row. .ethics-panel h2, .ethics-panel h3 is defensive styling with no counterpart in the rendered HTML: the panel’s leads are **bold** (so <strong>, not a heading), and the section’s own h2 is a sibling of the panel div rather than a descendant.
    • Auditing it would have reported a contrast figure for text that never appears. If you do put a heading inside the panel, add the row.

Current status: all 22 audited pairs reach AAA.

  • The last AA-only pair was 02-modern-cards’s red section headings on white (6.28:1 against a 7:1 bar).
  • Raising them from 1.1rem to 1.5rem makes them “large text”, where the bar is 4.5:1, which was preferable to darkening the brand red.
  • Because every pair now clears AAA, --require-aaa is a usable gate rather than an aspiration so CI runs it that way.

2 _brand.yml and your workflow

As flagged on the Home page, Quarto’s brand theming is still evolving. This section describes how _brand.yml fits into these templates today; see Quarto’s own Brand guide (Posit Software, PBC, n.d.) for the full, current spec.

What it’s for here:

  • _brand.yml is the single source of the AU color palette and typography.
  • Quarto’s brand-aware HTML theming reads it automatically, you don’t include or reference it from any .qmd, Quarto just picks it up from the project root.

What it actually reaches:

  • In practice, only the web (html) output consumes it directly for color, via Bootstrap variables Quarto derives from the brand palette, e.g., --bs-body-color, --bs-code-color, --bs-link-color.
    • See the “Bootstrap var” rows above.
  • The print (poster-typst) output does not read _brand.yml’s color palette at all.
    • Print colors come from each template’s own YAML (footer-color, footer-text-color) and from raw Typst blocks, so a color change needs to be made in both places.
    • See step 5 of Fork this repo and build your poster.

Typography is the mirror image of color, and worth calling out on its own.

  • _brand.yml declares Source Sans 3 and STIX Two Text as typography.fonts resources (source: google).
  • For print, this is confirmed working: poster.typ hardcodes STIX Two Text for the body, Quarto injects a Source Sans 3 show rule for headings, and Quarto fetches both from Google into .quarto/typst/fonts/ at render time, verified by the absence of Typst’s unknown font family warning, which is a hard compiler signal, not a guess.
  • For web, this is also confirmed working.
    • An earlier approach grepped the raw rendered HTML for literal strings like @font-face, but every poster.qmd sets embed-resources: true, which makes Quarto inline its CSS as percent-encoded data:text/css,... URIs rather than plain <style> text, so @font-face appears in the file as %40font%2Dface and a literal-string search never finds it.
      • Decoding those URIs (rather than grepping around them) now shows the rendered HTML for each template does contain a self-hosted @font-face for Source Sans 3 (base64-embedded font data, not a hotlink) and --bs-body-font-family: Source Sans 3 in the compiled Bootstrap variables and font-family:Source Sans 3 on the compiled heading rules, i.e., both the base and headings roles reach the browser correctly.
    • STIX Two Text is fetched and embedded too, but is never applied to anything on the web side, and correctly so, since _brand.yml’s own comment notes it’s declared only so Typst can find it for print; nothing under base/headings names it for html.
    • scripts/render-all.R now has a check_fonts() step that decodes each rendered poster.html this way and asserts the @font-face block and --bs-body-font-family variable are both present, so a future regression, or another naive grep, fails loudly instead of silently reading as “not delivered.”
  • See AGENTS.md’s “Fonts” section for the full before/after and for how the standalone minimal-reproduction project (no custom theme or scss) was re-run with the same decode-first approach and shows the identical, working pattern.

Why it’s kept in sync with the stylesheet by hand, not generated from it:

  • scss/poster-common.scss (Sass (Sass, n.d.)) defines the same $au-* tokens under scss:defaults for rules Bootstrap’s brand integration doesn’t cover (the banner gradient, the ethics panel, section-card styling).
    • Nothing currently generates one file from the other, so Re-coloring the templates treats both as required edits, and check-contrast.R reads both.

The logo: key is intentionally left unset because each template places the organization logo explicitly instead. See Shared resources to avoid Quarto rendering a second, automatic brand logo alongside it.

If you fork this for another organization:

  • Update _brand.yml’s palette and typography alongside scss/poster-common.scss and each template’s footer colors.
  • Then, re-run Rscript scripts/check-contrast.R --require-aaa to confirm the new combination is still accessible.
