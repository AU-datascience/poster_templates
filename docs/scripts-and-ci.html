Scripts & CI

1 Build & check scripts

scripts/ holds four R helpers, plus a shared registry they all read. All are optional, a plain quarto render still works.

  • Paths are resolved with the here package rather than requiring you to run from a specific working directory, and the template registry (scripts/templates.R) auto-discovers posters: either the multi-template layout shipped here (templates/<dir>/*.qmd, one per subdirectory), or, if you deleted templates/ and kept a single poster at the project’s top level under any filename, that one file instead.
Script What it does
render-all.R Renders every discovered template to both formats, then runs every check below (including delegating to check-contrast.R); one command for the whole suite. Exits non-zero on failure, so it can be wired into CI or a pre-commit hook. Pass --no-render to check existing output without re-rendering.
check-column-balance.R Measures how far down each Typst column the content actually reaches. Usable standalone: Rscript scripts/check-column-balance.R templates/<name>/poster.pdf <num-columns>.
make-previews.R Regenerates images/previews/preview-*.png and comparison.png from the rendered PDFs.
check-contrast.R Audits every foreground/background pair in the output against WCAG AA and AAA. Parses the palette, the stylesheets’ own color:/background: rules (including both linear-gradient() stops), and each template’s print footer YAML, so a re-color is re-audited rather than checked against a stale copy. Fails below AA, or below AAA with --require-aaa. See Re-coloring the templates.

scripts/templates.R is the shared registry of templates (column counts, print sizes, expected column-fill baselines) that the other three read, so adding a template to the multi-template layout is a one-line edit there; a template discovered outside that registry (e.g. a renamed single-poster fork) just runs without a column-balance baseline to compare against.

A Makefile (OSDev, n.d.) wraps the common commands:

make render       # clear the stale Typst package cache, then render + check everything
make check        # run the checks against whatever output already exists (no render)
make clean-cache  # just clear .quarto/typst/packages (see the caching note below)

Every check in render-all.R exists because that failure actually happened once during development and was invisible in the render log:

  • pages: a content edit overflowing onto a second Typst page; a poster must be exactly one page.
  • divider: the web section divider disappearing from the HTML.
  • acknowledgments: the raw-HTML-in-a-conditional-div bug described under Notes / gotchas, which dropped the acknowledgments, grant number, and References heading from print while the web version looked perfect.
  • ethics: the Ethics & Broader Impact panel missing from either format (it is written once per format, so it can go missing from one).
  • balance: a column emptying out relative to its measured baseline.
  • #### after show rule: a #### heading placed above the level-3 show rule described under Notes / gotchas. Typst show rules only affect what follows them, so such a heading silently keeps the package’s “1) Heading:” run-in style.
  • contrast: a palette edit dropping a color below WCAG AA, delegated to check-contrast.R so the same audit stays usable on its own.

1.1 Continuous integration

.github/workflows/posters.yml runs these same scripts on push and pull request via GitHub Actions (GitHub 2024), in three jobs (a workflow-authoring reference like (GitHub Actions Setup — Github_actions 2026), written for R packages specifically, is a useful pattern library even though this repo hand-writes its own YAML rather than generating it):

Job Runs Why
changes A dorny/paths-filter check against the diff — no R, no Quarto Cheap pre-check so the two jobs below only pay for a full R/Quarto toolchain install when their own inputs actually changed. Skipped only for a manual workflow_dispatch run, since there’s no diff to filter on.
contrast check-contrast.R --require-aaa Pure source parsing, no Quarto, no fonts, no rendering, so it is quick and its verdict is unambiguous. Every pair currently reaches AAA, so the strict gate is the meaningful one. Runs only when changes reports a color-relevant path touched (_brand.yml, scss/**, a template’s poster.qmd/*.scss, scripts/templates.R, scripts/check-contrast.R, or the vendored extension), or on manual dispatch.
render render-all.R (both formats for all three templates, plus every output check) Needs the Typst toolchain and system libraries for pdftools/magick, which are the fragile parts. Keeping it apart from contrast means a toolchain or font problem is never mistaken for an accessibility regression. Runs only when changes reports a render-relevant path touched (templates/**, scripts/**, _extensions/**, scss/**, _brand.yml, _quarto.yml, .quarto-version, or the workflow file itself), or on manual dispatch.

Both gates exist because a push touching none of those paths — a docs-only or README-only commit, say — previously still paid for the full job’s R/Quarto toolchain install regardless of relevance: 30-40 minutes observed for contrast alone, almost all of it a from-source tidyverse install with no cache, for an audit whose own logic runs in seconds. A job skipped this way reports as skipped rather than failing, which GitHub’s required-status-check logic treats as passing, so this is safe to use even where these jobs are required checks on main.

See AGENTS.md — an orientation file following the open AGENTS.md convention (Agentsmd/Agents.md 2026) for AI coding agents (and humans) working in a repo — for project orientation, the vendored extension’s local patches, and the open fonts issue.

Two caveats worth knowing before you rely on it:

  • Quarto’s release version matters. Both workflows pin quarto-dev/quarto-actions/setup@v2 to a specific Quarto version rather than tracking release; an unpinned run once picked up a pandoc/Typst-writer change that broke the institution-logo path substitution.
    • The version lives in one file, .quarto-version, which each workflow reads into a step output before calling setup@v2.
    • This way posters.yml and docs.yml cannot drift out of sync with each other the way two hardcoded copies could.
    • See Updating the pinned Quarto version below for the bump procedure, and why the pin stays even though the specific bug it was protecting against is now also patched at the source.
  • Fonts change layout, and layout is measured. poster.typ asks for STIX Two Text, and Quarto injects a Source Sans 3 show rule for headings; both are now declared as brand font resources in _brand.yml (source: google).
    • Quarto fetches and caches them under .quarto/typst/fonts/ at render time.
    • The GitHub runner needs no system fonts for the print render, and CI and local renders resolve the same faces by construction.
    • This is purely about print/CI reproducibility; see Theming & Brand for what the same _brand.yml declaration does – and doesn’t – deliver for the html output.

1.1.1 Updating the pinned Quarto version

Bump .quarto-version deliberately rather than letting either workflow drift to a new release silently:

  1. Install the candidate Quarto release locally.
  2. Run make check-quarto-version to confirm quarto --version matches the release you just installed (it fails loudly on a mismatch, so you know you are about to test the version you think you are).
  3. Run make render (renders every template and all output checks) and, if you touched docs-src/, quarto render docs-src too. Inspect the rendered PDFs/HTML, not just the check output – the balance/contrast checks catch some regressions, not all of them.
  4. Only once that looks right, edit .quarto-version and commit. Both posters.yml and docs.yml read the same file, so one edit updates both workflows.

Why the pin stays, even after the path fix. _extensions/quarto-ext/poster/typst-show.typ now strips a stray leading backslash from the substituted institution-logo path defensively (see Notes / gotchas), which patches the specific bug that originally motivated pinning.

  • That is not a reason to switch either workflow back to tracking release: the pin’s job is to make a render on a given commit reproducible run to run, and it was already carrying that weight for other reasons before this bug was ever found, e.g.. the font-resolution differences discussed in AGENTS.md.
  • A future pandoc/Typst-writer change breaking something else entirely (a different substitution, color handling, heading numbering) would be just as invisible under release as this one was, and there is no way to defensively patch a bug that hasn’t happened yet.
  • Tracking release trades a small, bounded maintenance cost (the four steps above, only needed when you actually want a newer Quarto) for an unbounded and unpredictable one (CI failing on an unrelated commit because GitHub’s runner picked up a new Quarto release overnight).

This documentation site itself is a separate, nested Quarto website project: sources live in docs-src/ (its own docs-src/_quarto.yml), rendering to docs/. GitHub Pages (Settings -> Pages: branch main, /docs) serves that committed docs/ folder directly; there’s no publish step in CI;

  • .github/workflows/docs.yml renders docs-src/ fresh and then diffs the result against the committed docs/, independent of the two jobs above.
  • If they differ, someone edited docs-src/ (or an image copy-images.sh pulls in) without re-rendering, a stale /docs is otherwise invisible in a PR diff, since docs-src/*.qmd changes review fine on their own.
  • After editing anything under docs-src/, re-render and commit the result: quarto render docs-src.
NoteThis is a simplified Pages setup, on purpose

The pattern here, render locally, commit the rendered docs/ folder, point GitHub Pages (Settings → Pages: branch main, /docs) at it directly, is not the only way to publish a Quarto site to GitHub Pages, and it is not what most production projects do.

  • It was chosen deliberately for this repo because it needs no GitHub Actions permissions, no deploy step, and no separate gh-pages branch to reason about: what’s on main in docs/ is exactly what’s live, and any contributor can quarto render docs-src locally and see precisely what will publish before pushing.

The trade-off is real, and worth knowing before copying this into your own repo:

  • Rendered HTML/CSS/JS lives in git history like any other tracked file, so PR diffs touching docs-src/ also carry a (usually large, machine-generated) diff of docs/.
  • Nothing enforces that docs/ actually matches docs-src/ at any given commit except a CI job (.github/workflows/docs.yml) that re-renders and diffs the two after the fact — it catches a forgotten re-render, but only after the commit is already up.
  • output-dir: ../docs pointing outside docs-src/’s own project directory is why quarto render docs-src prints the harmless-but-odd site_libs/“unexpected path configuration” warnings documented in AGENTS.md — an artifact of this specific layout, not a sign of anything broken.

When this simplified approach is a reasonable fit: a small site with one or a handful of maintainers, low-frequency publishing, and a preference for “no CI, no Actions permissions to configure, nothing to debug beyond a normal git commit.” That describes this repo.

When to reach instead for a proper build-and-deploy workflow (render to an ignored, in-project output directory like _site, then publish via actions/deploy-pages or quarto publish gh-pages, with GitHub Pages set to source from “GitHub Actions” rather than a branch): a site with many contributors, frequent changes, or a desire to keep generated files out of git entirely.

  • That is the more standard, more scalable pattern, and the one worth learning if you are setting up Pages for a repo of your own from scratch.

2 Forking vs. cloning: what runs, and how to control it

This repo ships two GitHub Actions workflows (posters.yml, docs.yml). What happens to them depends on how you got your own copy of the repo, and that trips people up often enough to spell out explicitly.

2.1 Forking (clicking GitHub’s “Fork” button)

GitHub copies the workflow files into your fork, but leaves Actions disabled on the fork by default. This is a deliberate, blanket security measure for every fork of a public repo, not specific to this one.

  • The first time you open your fork’s Actions tab, GitHub shows a banner (“Workflows aren’t being run on this fork”) with a button, “I understand my workflows, go ahead and enable them.”
    • Nothing runs, not a push, not a manual trigger, until you click it (or do the CLI equivalent below).
    • Once enabled, pushes to your fork’s branches trigger posters.yml/docs.yml exactly as they do here, using your fork’s own Actions minutes.
  • Opening a pull request from your fork back to this repo is different again.
    • That pull_request event runs under this repo’s Actions settings (already enabled), not your fork’s, but with two restrictions that apply to any fork’s PR, regardless of whether you enabled Actions on your fork:
    • The GITHUB_TOKEN the workflow gets is read-only and has no access to this repo’s secrets.
    • By default, a first-time contributor’s workflow run requires a maintainer to click Approve and run in the Actions tab before it executes at all.
    • Every run after your first merged contribution runs automatically.

2.2 Cloning (git clone + push to your own new repository, not a GitHub fork)

  • If you git clone this repo and push its history to a brand-new repository you created yourself (rather than using GitHub’s “Fork” button), none of the fork-specific restrictions above apply. — GitHub has no record that your repository descends from this one.
  • Actions are enabled by default on a new repository, the same as any other repo you create, subject only to your own account’s or organization’s Actions policy (Settings → Actions → General).
  • Your first push already triggers posters.yml/docs.yml, with no opt-in banner to click.
  • A plain local git clone with no push anywhere never triggers anything — workflow runs are a server-side GitHub event, not something git clone or a local quarto render can cause on its own.

2.3 Enabling/disabling from the command line

All of the following use the gh CLI and require admin access to the repository in question (your fork, or your own clone-turned-repo).

Permanently enable or disable Actions for the whole repository is the CLI equivalent of the fork’s “enable workflows” banner, or of Settings → Actions → General → Actions permissions:

gh api -X PUT repos/OWNER/REPO/actions/permissions -f enabled=true   # or false

Permanently enable or disable one specific workflow (leaves the rest, and the repo-wide switch above, untouched):

gh workflow disable posters.yml   # stops it from running or being manually triggered
gh workflow enable posters.yml    # re-enables it

Run a workflow exactly once, without changing either persistent switch above. Both posters.yml and docs.yml declare workflow_dispatch as a trigger already, so a single on-demand run (Actions enabled, this workflow not disabled) is:

gh workflow run posters.yml --ref main

This queues one run of the current main (or whatever --ref you give it) and leaves the workflow’s enabled/disabled state exactly as it was before and after, unlike gh workflow disable/enable, which persist until you change them again.

3 Notes / gotchas

The vendored _extensions/quarto-ext/poster has local patches. If you re-install/update the extension, re-apply all of them:

  • poster.typ accepts the institution logo as already-loaded Typst content (loaded once in typst-show.typ) rather than a bare path string, because Typst packages cannot read files outside their own package directory (see the _univ_logo_img handling in typst-show.typ).
  • poster.typ / typst-show.typ add a footer-text-color format option (defaults to white) so the footer text stays legible against dark footer-color values. Set it to a dark color if you pick a light footer background (see 01-classic-academic’s footer-text-color: "25406A").
  • biblio.typ (a new template-partial, registered in _extension.yml) sets title: none on the generated #bibliography(...) call, so Typst’s own default “Bibliography” heading doesn’t duplicate each template’s own #### References heading.
  • poster.typ also scales the footer’s font sizes down (never up) on posters narrower than the extension’s documented 36in default, so the footer row (URL + text + emails, packed with h(1fr) spacers) doesn’t wrap outside its colored background block on narrower prints like 03-minimal-story’s 24in width.
  • typst-show.typ strips a stray leading backslash from the substituted institution-logo path before calling image() on it, defending against a pandoc/Typst-writer bug that once inserted one and broke the render with “path must not contain a backslash” (see Updating the pinned Quarto version).
    • It is a no-op when the path is already clean, so it is safe regardless of Quarto version.
    • Because Quarto caches the vendored local Typst package under each project’s .quarto/typst/packages/local/typst-poster/, edits to poster.typ only take effect after that cached copy is refreshed (delete .quarto/ or copy the updated file over it, or just run make render). A plain quarto render will silently keep using the stale cached version.
  • Every template’s poster-typst format sets fig-format: png. Without it, Typst’s default (fig-format: svg) asks R’s Cairo graphics device to render each plot, which can fail with a missing X11/Cairo shared-library error on machines without XQuartz (common on Apple Silicon macOS, and on Linux without libcairo2-dev).
    • Installing XQuartz/libcairo dev packages fixes it at the source; fig-format: png sidesteps it by using R’s built-in PNG device instead, at a small cost in image sharpness for print.
  • Never put a raw <hr> (or other raw HTML) inside a ::: {.content-visible when-format="html"} div. Doing so silently discards every element after it in the Typst output – the templates lost their section divider, the entire Acknowledgments block (advisor, grant number, code/data link), and the #### References heading from the printed PDF, while still rendering fine on the web. Use a ```{=html} raw block instead, which HTML picks up and Typst ignores cleanly.
  • Column balance: the shipped samples do not fill their columns evenly, and that is accepted slack rather than a bug – 02-modern-cards reaches ~44% down column 1 vs ~82% down column 2, and 03-minimal-story ends ~79% down its single column. The Evidence figure is one ~10in-tall indivisible block, so moving 02’s #colbreak() past it only inverts the gap (measured 91%/29%, a wider spread). Real content is the remedy. Baselines live in scripts/templates.R; render-all.R fails on a drop of more than 10 points from them.
  • Web banner contrast: the title banner is a gradient, so banner text must clear its lighter stop, not just the dark one.
    • The original $au-light-blue author/date color measured 6.97:1 on navy but only 3.59:1 on the $au-blue stop, a WCAG AA failure.
    • All banner text is now plain white on a darkened light stop ($au-blue-banner, 7.21:1), and link and grey body text were darkened to clear AAA too.
    • See Re-coloring the templates, and run Rscript scripts/check-contrast.R after any color change.
  • #### headings arrive as Typst level 3, not level 4. Quarto maps markdown ## to =, shifting every heading up one level, so the closing-matter headings land on the poster package’s level-3 style: a numbered, italic, colon-terminated run-in that prints as “1) Acknowledgments:” and reads like a numbered list item.
    • Each template overrides this with a #show heading.where(level: 3) rule in the raw Typst block just above #### Acknowledgments, defined after the package’s own show heading rule so it takes precedence.
    • A #### heading placed earlier in the poster still gets the package’s run-in style, since Typst show rules only apply to content after them.
  • Font-size hierarchy is not automatic. The poster package defaults title-font-size to 48pt and authors-font-size to 36pt, and derives level-1 headings as body-font-size + 16.
    • If you shrink title-font-size to fit a long title (as 03-minimal-story needs to at 24in wide), lower authors-font-size too and keep the title above body-font-size + 16, or the author line and section headings will print larger than the title.
  • .quarto/, rendered *.pdf/*.typ/poster.html, and *_files/ directories are gitignored as build output.
